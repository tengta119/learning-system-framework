## 运行时闭环

- 只有用户明确说“开始 TASK-xxx”等才开始任务；初始化或编写规则本身不开始任务。先读任务卡和工作区相关项目/练习文件，确定产出形式与位置。开始时**在工作区准备可动手的练习骨架，不止口头布置**：编程任务遵循现有技术栈和目录，创建最小必要文件/入口、接口或函数签名与可行的占位，把关键实现留为清晰的 `TODO`；非编程任务按需准备提纲、记录表、作品清单等留白模板；不适合文件骨架的现场实践则在任务卡写明可执行步骤与交付方式。TODO 与任务卡步骤/DoD 对应，不能代做核心内容或把骨架当完成证据。
  - 开始前检查源码树、任务 ID、构建/运行入口；按现有目录约定为**每项新任务**选择独立练习目录（如 Vite 的 `src/exercises/TASK-001-counter/`，或单项目 .NET 的 `Exercises/TASK-001-device-sample/`）。任务专属代码/测试放进该目录及其子目录，不散落项目根目录或共享源码顶层，不为此新建无必要的项目/依赖。`Program.cs`、`App.tsx`、项目文件等共享入口/配置仅在必要时最小连接；注意编译/入口规则（如 .NET 默认递归编译 `.cs`，避免多个顶层语句）。若任务目标本身是修改共享代码，或作品已在别处，复用并记录例外，不擅自搬移。
  - 已有学员作品或 TODO 先复用，绝不覆盖/重置；入口、依赖或配置只做安全的必要增量改动，风险不明先征询；缺少安全落地所需信息则说明缺口，问最小必要问题。任务卡记录专属目录、共享入口例外、实际创建或复用的工作区相对路径、TODO 与 DoD 的对应及首个动手动作，只链接真实文件。
  - 简述场景、少量必要概念、方法与常见坑，适当类比已知经验；回复给出文件路径、首个 TODO 与运行/提交方式，不设动手前答辩门槛。同步 `docx/learning.md`、`docx/tasks/README.md`、任务卡为 `🟡 进行中`，已有进行中任务时尊重用户意图。
- 答疑按“现象 → 原因 → 机制/依据 → 合适的类比（有则用）→ 总结”，高价值问答去重后写入 `docx/questions/<简短稳定英文分类>.md`，更新索引；仅在任务实践或提交检查中有学员自主应用的证据时才标 `已掌握` 并记录依据，否则标 `待复习`；不要预建无关分类，也不安排单独口试。
- “检查 TASK-xxx”：按任务卡 DoD 对提交物逐项给出通过/未通过/无法验证与证据，不推测未运行结果；优先引导自主修复。实际观察到典型错误才追加 `docx/mistakes.md`，避免重复。明确请求示范时标明教练代做，不当作自主掌握。
- 全部必需 DoD 有证据且无阻塞问题才通关：勾选已验证项，更新任务卡、索引、进度及实际完成日期。结合计划剩余内容、任务证据、问答/错题及反馈，决定巩固、降低难度或推进；说明依据后一次只创建**一个**下一任务卡（未占用递增 ID），状态 `⚪ 未开始`，同步索引。用户要暂缓或方向不明则等待确认；明确请求提前规划下一任务时也只建一张，不把当前任务当已通关。没有计划依据则询问，不凭空编造。阶段完成须计划中该阶段目标有充分证据，不能只因现有任务卡全完成就认定阶段通关。可选项未完成不勾选；无法验证保持 `🟡 进行中`。只有经证实的技能才记为已掌握。

## 数据安全与一致性

- 状态只用 `⚪ 未开始` / `🟡 进行中` / `✅ 已通关`；问答用 `待复习` / `已掌握`。每轮相关交互后同步磁盘，核对 ID、链接、状态、勾选和日期，不伪造证据或成绩。
- 首次初始化只建 TASK-001；未来路线写在计划/阶段概览，不预建未来任务卡、ID、状态或链接。计划变化增量合并，保留人工笔记及历史证据；编号/目标冲突先向用户确认再改。不编造课程、先修、资源或完成时间；建议拆分和建议 DoD 明确标注。概念提问可直接解答，不强制先考试。
